# dotViewer 1.5.6 (13) — release verification

Released 2026-09-22 from tag `v1.5.6` (`00be50bafe0d2b05dbcc2d5efa0c62a6a7ac417d`), fast-forwarded onto `main` without a PR.

## Distribution

- Published through `scripts/publish.sh 1.5.6 --build-number=13`. Running it without the flag fails before any side effect: macOS `/bin/bash` 3.2 treats the empty `RELEASE_ARGS` array as unbound under `set -u` (1.5.5 was published with `--build-number=12`, which masked it).
- One pass: archive → Developer ID export → signature and provisioning checks → app notarized, stapled, Gatekeeper → styled DropDMG installer (profile `dotviewer`) → DMG notarized, stapled, Gatekeeper → checksum → tag → GitHub release → Homebrew tap.
- Public DMG SHA-256: `eecb901cf8207896e8318e7f589bc599ab1f0e1d650ffba7daf75e8811e8645b`. Matches the local DMG, the released `.sha256` asset and the Homebrew cask.
- GitHub release is marked Latest (not draft or prerelease). Assets: `dotViewer-1.5.6.dmg` (70,244,822 bytes) and its `.sha256`.
- Exported app and the app inside the mounted DMG pass `codesign --verify --deep --strict`, Gatekeeper (`Notarized Developer ID`) and Developer ID provisioning validation for all six bundles — the check that rejects the broken 1.5.4. App and DMG staple validation pass. App, preview and thumbnail executables are universal (`x86_64 arm64`).
- Public website `/download` shows 1.5.6; `/download/latest` redirects (307) to the 1.5.6 GitHub DMG.

## Regression verification

- XCTest: 242 tests, zero failures, including the new `SettingsTabBarTests`, `GnuplotSourceDetectorTests` and custom-mapping precedence tests.
- Python: 20 tests passed. UTI coverage checker: all extensions covered.
- Gnuplot detector on the 11 scripts reported unrecognised in #29: 1.5.5 detects 0/11, 1.5.6 detects 11/11. A PARI/GP corpus stays plain text.
- Installed 1.5.6 in place over the 1.5.5 release (same Developer ID designated requirement; 1.5.5 backed up to the session scratchpad). Cold launch reaches "Extension Enabled — dotViewer is ready", no conflicts, footer v1.5.6. Both extensions register from `/Applications` at 1.5.6.
- Accessibility survived the in-place upgrade: Settings → Preview UI shows "⌘F search is active" and "Accessibility access granted".
- Quick Look smoke on the installed release (`qlmanage -p`, debug routing logs): two #29 scripts → `gnuplot`, a PARI/GP script → `plaintext`, JSON control → `json`; HTML built for all four.
- Settings sub-tabs switch in the shipped build (Window → Theme, narrow window on the scroll fallback). The automation delivered those as accessibility presses, not raw mouse events; the raw-mouse path is covered by `SettingsTabBarTests`.
